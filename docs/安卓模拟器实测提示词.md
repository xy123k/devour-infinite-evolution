# 《吞噬·无限进化》安卓模拟器实测提示词

你是资深手游测试工程师，请在 Windows 上启动 Android 模拟器运行《吞噬·无限进化》，按下面清单逐项实测，验证近期修改是否完成，并重点排查玩家容易触发的 bug。

## 一、环境准备

1. 启动模拟器（AVD 名 focus_test）：
   `D:\AndroidDev\sdk\emulator\emulator.exe -avd focus_test`
   首次启动约 1~3 分钟，等待进入桌面（可用 `D:\AndroidDev\sdk\platform-tools\adb.exe devices` 确认设备在线）。
2. 启动游戏本地服务（宿主机 Windows 上执行）：
   `cd D:\桌面\吞噬·无限进化` 然后 `python -m http.server 8765 --bind 127.0.0.1`
3. 在模拟器浏览器访问：`http://10.0.2.2:8765/index.html`（10.0.2.2 是模拟器访问宿主机的固定地址）
   - 若玩家已提供 GitHub Pages 地址，优先用 GitHub 地址测试，10.0.2.2 作为备选。
4. 需要时可用 adb 截图：`adb exec-out screencap -p > shot.png`

## 三、玩家易触发 bug 专项排查（重点，逐项实测）

1. **新手流程**：清除数据后首次进入，走完引导（跳过/下一步），确认引导不被卡住、五维说明与属性面板一致。
2. **快速连点**：
   - 探索前进连续快速点击（是否重复触发事件/敌人/重复扣资源）
   - 战斗按钮（普攻/技能）快速连点（是否卡死、重复结算）
   - 抽奖"启动装置/继续抽奖"快速连点（是否重复扣 30 精华/动画叠加）
   - 结算弹窗"确认领取"连点（是否重复结算）
3. **资源边界**：金币 <30 时点"启动装置"（提示是否友好）；金币 0 时进商店购买（是否提示不足、按钮禁用）。
4. **导航状态冲突**：
   - 战斗中点"天赋/状态/背包/共生体/更多功能/角色"各按钮，再返回战斗，确认战斗状态不丢
   - 事件/商人/转盘展示中点"主页/天赋"等，再回来，确认事件不卡、可继续
   - 轮回空间弹窗开着时点其他入口
5. **战斗边界**：快速狩猎按钮、逃跑按钮、Boss 战、精英战；敌人死亡瞬间点按钮。
6. **弹窗/浮层叠加**：tooltip（天赋/碎片/共生体）与结算弹窗、转盘动画同屏时是否遮挡错乱。
7. **转盘细节**：动画期间能否误触（应禁用）；动画结束后"继续抽奖"连点多次是否正常扣费和出奖；金币不足时"继续抽奖"。
8. **死亡与轮回**：战败→死亡结算弹窗（50%/55%一致）→轮回空间→开始轮回→永久成长显示正确。
9. **断线/刷新**：刷新页面（或清除缓存重进）后进度是否丢失、版本号是否正确加载（避免旧缓存）。
10. **竖屏适配**：手机竖屏分辨率下按钮是否被遮挡/重叠/溢出（重点：底部导航、事件卡、转盘、结算弹窗）。

## 四、报告要求

输出一份 Markdown 测试报告，包含：
1. 环境信息：模拟器 AVD、分辨率、浏览器、游戏入口地址、版本号（页面加载的 game.js?v= 值）。
2. **回归验证表**：上表 9 项逐项 PASS/FAIL + 证据截图（每项至少 1 张）。
3. **Bug 列表**：每个 bug 给复现步骤、期望行为、实际行为、严重级别（致命/严重/一般/建议）、截图。
4. **玩家最容易触发 TOP5**：按触发概率×影响排序，给出最可能被玩家遇到的前 5 个问题。
5. 明确区分：哪些是"修改未生效/改坏了"（需修复），哪些是"原有设计问题"。

注意事项：
- 每一步操作前先截图确认界面状态，不要凭猜测下结论。
- 发现疑似 bug 时先用最小步骤复现 2 次确认，再写进报告。
- 不要修改游戏文件，只做测试和报告。
