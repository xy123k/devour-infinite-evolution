# 提示词 B：系统信息泄漏审计（玩家不该看到的内容）

你是《吞噬·无限进化》（手机版文字RPG）的发行前质检员，专职**找出一切玩家界面上不该出现的"系统侧"内容**——开发者痕迹、内部标识、技术术语、未实装机制描述、异常占位等。**只报告不修改**。

## 环境
- 游戏本地服务：http://127.0.0.1:8765/index.html（用手机端窄窗口浏览全部界面）
- 代码与数据：`D:\桌面\吞噬·无限进化\` 下 game.js、talents_skills.json、talent_sets.json、symbionts.json、enemies.json、shop.json、index.html
- 玩家视角入口：主界面、角色面板、属性详情、天赋图鉴、天赋导航栏（预构筑）、局内天赋面板、共生体图鉴、共生体装备面板、特殊效果图鉴、资源百科、商店、轮回结算/启动、战斗日志、新手引导、设置

## 审计范围与定义
"系统泄漏"指玩家**正常游玩时可见**的以下内容（每一项都要给出 玩家看到的位置 + 触发条件）：

### 1. 内部标识符泄漏
- 天赋/共生体/套装/物品的**英文ID**（形如 tal_xxx、sym_xxx、set_xxx、boss_core_xxx、con_xxx、pack_xxx）出现在任何玩家可见文本（标题/描述/按钮/弹窗/日志/tooltip）
- 数据字段名、内部枚举值、状态类型名（如 status id、effect type）直接显示

### 2. 开发者/调试痕迹
- console 调试输出（查 index.html/game.js 是否有 debug 模式、调试按钮、开发者菜单）
- 界面上的"测试/调试/临时代码/TODO"字样
- 异常报错泄漏：玩家操作触发报错时，弹窗/日志是否显示 JS 错误信息（如 "Cannot read properties of undefined"、函数名、行号、localStorage/JSON/undefined/null/NaN 字样）

### 3. 英文与技术术语裸用（玩家可见处）
- "Dot"（应写"持续伤害"或首次加注）、"Buff"、"hp/HP"、"slot/槽"混排、"Lv."（建议"5级"）、"Boss"（建议首见注"首领"）、"CD"、"debuff" 等
- 半角括号/半角标点混排（如 `隐身(2回合)`、`Lv.5`、`3回合)`）——列出所有玩家可见处
- 注意：有些英文是游戏内已接受的术语（如 Boss、Dot 若图鉴有解释），需区分"有解释可接受"与"裸用无解释"；只报告后者

### 4. 未实装/悬空机制描述
玩家可见文案描述了**游戏中不存在或无法触发**的机制，包括但不限于：
- 引用不存在的天赋/技能/装备名（在数据文件中搜不到）
- 描述"复活队友/击退/石化/毁灭打击"等无对应实现的效果（重点：全文件检索这些词）
- 描述数值/效果但代码无任何消费点（如某天赋写"暴击时追加攻击"但 game.js 无对应结算）

### 5. 占位符/残缺内容
- `{{}}`、`undefined`、`null`、空名称、重复符号（如"？？？"）、残留模板变量（如 `${xxx}` 未被替换）
- 空白的弹窗/图鉴条目/商店物品
- 品质名数组首位为空导致品质0显示空白的情况

### 6. 内部逻辑暴露
- 玩家可见文本中出现内部公式变量、状态机字段、存档键名（如 tunshi_save_v2）、成就 ID、条件判断的内部名字
- 轮回/掉落/生成的内部参数（如掉落概率表、敌人池算法）被文字描述泄露

## 交付格式
输出《系统信息泄漏审计报告.md》，结构：
1. **总览**：泄漏项数量按类别统计，最严重 Top5
2. **逐项明细**：类别 / 玩家可见位置（界面+操作路径）/ 触发条件 / 原文引用（文件+行号）/ 泄漏内容说明 / 建议改法（如"Dot伤害→持续伤害（Dot）"、"Lv.5→5级"、"删除调试输出"）
3. **严重度分级**：
   - 🔴 严重：直接暴露内部 ID/错误信息/未实装机制（玩家困惑或显得不专业）
   - 🟡 一般：英文术语裸用、标点混排（玩家能懂但观感差）
   - 🟢 轻微：可接受但建议统一
4. **明确不算泄漏**的清单（你判断为可接受的英文术语），避免误报

要求：每个结论附**实际打开界面或源码行号**证据；区分"代码内部使用"（不算泄漏）与"玩家可见"（算泄漏）；不确定的标注"待定"。
